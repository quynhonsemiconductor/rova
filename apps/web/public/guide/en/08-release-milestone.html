Rova User Guide / 08. Release & Milestone
PART 08 · RELEASE & MILESTONE

Manage delivery milestones and read progress in the right place

Release identifies a Project delivery window. Milestone records milestones and can link multiple Releases. Create and edit these two objects at Plan → Timeboxes; See Release progress here Portfolio → Release Tracking.

After this chapter, you will be able to
  • Select the correct Release monitoring or management screen.
  • Create Release with valid date and status.
  • Create Milestones and understand when dates are entered manually.
  • Link Work Item, Feature or Epic to the correct Artifacts type.
  • Read data groups and Burnup charts in Release Tracking.
08.1

Select the correct screen before operating

Release information and progress metrics are in two different areas.

When neededOpen atDone here
Create or edit ReleasePlan → Timeboxes → ReleasesManage Name, Theme, date, status, metadata, Release Notes and Artifacts.
Create or edit MilestonePlan → Timeboxes → MilestonesManage milestones, target dates, Owner, Project/Team scope, Release links and Artifacts.
Read Release progressPortfolio → Release TrackingRead Feature/Work Item groups, status by Points or Count and Burnup chart.

Access rights: Workspace Admin and Project Admin can manage Release/Milestone within the allowed scope. Editor does not use these planning screens. Before proceeding, check Project and Team on the top bar.

Do not create Release in Release Tracking. This is the monitor screen. Release Planning and Dependencies analysis are not active functions in this guide.

08.2

Create Release

Use Release when you need to determine the time period and target for a Project delivery.

Before you start: select the correct Project, prepare the Release name, start date, expected delivery date and initial status.

FieldWhat to enterNote
Release nameShort name for the delivery.Required and should be distinguishable from other Releases.
ThemeMain goal or topic.Details can be added later.
Start Date / Release DateEstimated time period.Release Date cannot be earlier than Start Date.
StatusPlanning, Active or Accepted.This is the Release state, independent of the US/DE state.
DescriptionShort description or notes.Do not use in place of detailed Release Notes.
  1. 1
    Open Plan → Timeboxes

    In the Timebox selector, select Releases. The list only displays Release of the current Project.

  2. 2
    Select Add New

    The Create Release form opens with the Release name, Theme, Start Date, Release Date, Status and Description fields.

  3. 3
    Enter name, date and status

    Select Planning while Release is still preparing; Active when the delivery is taking place; Accepted when the result has been accepted.

  4. 4
    Choose how to complete

    Create Release saves and returns to the list. Create with details opens the Release Detail page to add metadata and detailed content.

  5. 5
    Check the newly created Release

    Compare name, Project, date and State on the list or Release Detail before assigning Work Item.

In Release Detail, you can add Release Theme, Notes & Scope Deliverables, Release Notes, Planned Velocity, Plan Estimate and Version. This page does not show Burnup or Accepted progress; Those numbers are in Release Tracking.

08.3

Create Milestone

Use Milestone for a demo, acceptance, or milestone that may span multiple Releases.

  1. 1
    Open Plan → Timeboxes → Milestones

    The screen displays Name, Target Start Date, Target End Date and Status.

  2. 2
    Select Add New

    Enter Milestone name; Select Status, Owner and add Description or Notes as needed.

  3. 3
    Select Date or Release link

    If Associated Releases is not selected, enter Target Start and Target End. If one or more Releases are selected, the target date will be calculated from those Releases.

  4. 4
    Select Create Milestone

    After saving, open Milestone Detail to check the date, status, Release link and Project/Team scope.

Milestone status includes Planned, At Risk, Met, Missed, Cancelled and Completed. This is the state of the mold; Do not use in place of Release status or Work Item status.

Milestone has no velocity, Task Estimate or Iteration carry-over rules.

08.4

Understand links and target dates

Release and Milestone can be created in any order and are associated many-to-many.

Link statusHow to determine Milestone dateWhen changing
There is no associated ReleaseTarget Start and Target End are entered manually.Authorized users can edit directly for two days.
There is a ReleaseGet the Start Date and Release Date of that Release.Milestone date becomes inferred value.
There are many ReleasesTarget Start is the earliest start date; Target End is the latest delivery date.Changing the Release list will recalculate the date range.
Uninstall all ReleaseMilestone returns to manual date entry mode.Check and re-enter the appropriate date before saving.

Release and Milestone are two independent relationships on Work Item. Change the Release of a US/DE does not delete itself selected Milestones. When a Work Item has a Release, the new Milestones to Add list displays only the Milestones associated with that Release.

08.5

Manage Artifacts of the correct type

Artifacts are Work Items or Portfolio Items associated with a Release or Milestone.

ScopeArtifacts are validRules to remember
ReleaseUser Story, Defect and Feature are assigned directly.Each US/DE can only have a maximum of one Release. Task and Epic are not Release Artifact.
MilestoneStory, Defect, Feature and Epic; may include descendants inherited from Feature/Epic.A Work Item can belong to many Milestones if it is still within the valid scope.
  1. 1
    Assign Release from Work Item or Feature

    Open the appropriate Backlog, Work Item Detail or Portfolio Item and select Release. Selecting another Release will replace the old Release link but will not change the Iteration or Milestone.

  2. 2
    Check the Release Artifacts tab

    Open Release Detail → Artifacts to find and check the linked items. Add Artifact allows choosing an existing Story/Defect; This operation does not create a new Work Item.

  3. 3
    Assign Milestone using multi-select list

    On the Work Item, select one or more valid Milestones. The selected Milestones must remain visible when you reopen the field.

  4. 4
    Check Milestone Artifacts

    Compare directly assigned items and items inherited through Feature/Epic. Duplicate data must be counted only once.

Do not use Add Artifact to replace the Work Item creation flow. When you need to create a new US/DE or Feature, create it in Backlog or Portfolio and then assign Release/Milestone to the correct field of the object.

08.6

Read Release Tracking

Use Portfolio → Release Tracking to view the scope and progress of the currently selected Release.

  1. 1
    Check Project and Team

    Release Tracking uses global scope on the header bar. Switching Team will recalculate the list and chart; the page does not have a second Project/Team filter.

  2. 2
    Select Release

    Use the previous button, the Release list and the following button at the top of the page. The date range next to the name is what the Release window is reading.

  3. 3
    Select Chart Unit

    Points plus Plan Estimate of Story/Defect; Count counts Story/Defect. This selection applies to both the Status and Burnup columns.

  4. 4
    Select the group to view

    Features in Release is a directly assigned Feature; Derived Features is a Feature that appears because there is a child Story/Defect in Release; Unparented Stories & Defects is an item without a parent Feature.

  5. 5
    Read Status and Burnup

    Planned takes Story/Defect of Release. Accepted only counts items in Accepted or Release status; Completed is not considered Accepted.

Burnup chart displays Accepted, Planned, Preliminary Estimate and target line in the Release window. The Iteration line below helps compare the cycles passing through that time period.

Historical void is not zero. Dates without snapshots are displayed as blanks. Do not conclude that progress is zero if the history is lacking or incomplete.

Dependencies · Future is just a label for future functionality; Do not use it to assess dependency risk in the current version.

08.7

Troubleshooting

Check permissions, scope, and relationships before regenerating data.

01
Release or Milestone not found

Check the correct Project, uncheck Search/Filters and confirm the account has Workspace Admin or Admin rights at that Project.

02
Cannot create or edit

Editor does not have permission to manage Timeboxes. Contact Project Admin instead of requesting additional Team membership.

03
Milestone date cannot be adjusted

Milestone is binding at least one Release so the date is inferred. Check Associated Releases before changing associations.

05
Item not available in Release Artifacts

Compare Project, item type and Release field. US/DE may be in another Release; Task and Epic do not appear in this list.

06
No Milestone to select on Work Item

If the item already has a Release, only the Milestone associated with that Release is included in the new selection list. Previously selected Milestones do not disappear.

07
Burnup is blank or broken

Check Release, Team scope, Unit Chart and history quality. Snapshot space is not interpreted as zero.

Check yourself before moving on to the next section
  • Do you know where to create Release is different from where to read Release Tracking?
  • Do you know when the Milestone date was hand-entered or inferred?
  • Have you distinguished Release Artifact from Milestone Artifact?
  • Do you know that Completed is not counted as Accepted in Release Tracking?
