Rova User Guide/01. Introduction
PART 01 · GETTING FAMILIARIZED

Understand the structure before starting work

Rova organizes data in three coverage classes: Workspace → Project → Team The system then uses different object types to describe goals, tasks, and delivery plans.

After this, you will understand
  • In what scope am I working?
  • How are Epic, Feature, US, DE and Task different?
  • What are Iteration, Release and Milestone used for?
  • How is access different from creator and owner?
01.1

Three layers of work scope

The scope being selected determines what data you see and who can be selected as Owner.

01
COMPANY SCOPE

Workspace

Common space of the organization. Workspace contains users and Projects.

For example: QNSC
›
02
PRODUCT SCOPE

Project

A place where the work, plans, and reports of a product or initiative come together.

For example: Rova
›
03
SCOPE OF IMPLEMENTATION

Team

The group performs work in Project. A Project can have many Teams.

For example: Maintainer
Scope and permissions are two different things

Select a Project or Team that does not automatically grant additional permissions. If you don't see the expected data, check both the selected scope and the permissions granted.

01.2

Work item types

Start from a large goal, then divide it into components that can be assigned to the Team and specific tasks.

EP

Epic

Large goal at the Project level, used to group Features with the same result direction.

FE

Feature

A product capability that can be deployed by the Team. Feature can belong to an Epic.

US

User Story

The need to bring value to users. US can be associated with a Feature.

DE

Defect

Error needs to be tracked and resolved. DE can be associated with a Feature and a Parent Story.

TA

Task

Specific implementation. Task is always a direct child of a US or DE.

The entire string is not required

A US/DE may not have associated Feature; A Feature may not be part of Epic yet. Tasks always need a parent US or DE.

Do not use Epic instead of Project

Project is a scope containing data. Epic is the target audience within a Project.

US and DE are two peer types

Both are Work Items and can have child Tasks. DE has its own error handling lifecycle.

01.3

Three planning objects

Iteration, Release, and Milestone add timing context to Work Items; they are not three consecutive parent–child levels.

IT

Iteration

Short working time for Team to perform a US/DE group. Work Items that have not yet entered Iteration are considered Unscheduled and is in the Backlog.

Used to answerWhat does Team do in this cycle?
RE

Release

A delivery has its own time period and status. US/DE can be attached to a maximum of one Release.

Used to answerWhich deliveries are the work aimed at?
MI

Milestone

Important milestone to track. A Milestone can link multiple Releases and span multiple Projects or Teams.

Used to answerWhat important milestones need to be achieved?
Don't read these planning objects as a tree

A US/DE can simultaneously belong to an Iteration, a Release and many Milestones. Each link serves a different management purpose.

01.4

Access rights and responsibilities

Rova uses scope permissions. Role names such as PM, BA, Developer, or QA do not automatically determine which button you can use.

PermissionsScopeDescription
Workspace AdminComplete WorkspaceManage users, Projects, Teams and access rights. Team membership only determines participation in operations and the ability to be selected as an Owner in the Team.
AdminOne Project · All TeamsManage delivery activities in the assigned Project; Do not self-administer the Workspace structure.
EditorA Project · assigned TeamsCreating and updating tasks in Teams is allowed; Do not access out-of-scope planning or administrative functions.
Project not assignedNo Project scopeProject does not appear and direct path is denied. This is a state of lack of rights, not a right to choose.
Example of Workspace Admin and Owner

Workspace Admin can still create US/DE thanks to Workspace permissions. However, their name can only be selected as Owner when they are a valid member of the Team being selected.

EXAMPLE

Improved search experience

Team Maintainer prepares a search enhancement for the next delivery.

QNSC›Rova›Maintainer
  1. EP
    Epic: Enhance user experience

    Big goal at Project level.

  2. FE
    Feature: Advanced search

    Product capabilities belong to Epic and are deployed by the Team.

  3. US
    User Story: Filter results by Priority

    Specific user needs, associated with Feature.

  4. TA
    Task: Build Priority filter

    The concrete implementation, is a child of the User Story.
