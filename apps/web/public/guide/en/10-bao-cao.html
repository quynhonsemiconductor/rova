Rova User Guide / 10. Reports
PART 10 · REPORT

Read progress from the correct data source

Rova provides three read-only reports: Iteration Burndown tracks remaining work each day, Velocity compares results across completed Iterations and Team Capacity summarizes Capacity at the current Task time.

After this chapter, you will be able to
  • Select the correct report for the question to answer.
  • Read Burndown without confusing Hours with Points.
  • Distinguish between Accepted During, After and Not Accepted.
  • Read Capacity, Estimate, ToDo and Actual by Team.
  • Detect zeros, empty data, and no history.
10.1

Select the correct report

Each report answers a question and uses a different data source.

When you need to knowSelect TypeTime range
Is the remaining work reduced as planned?Iteration BurndownAn Iteration is selected.
How many Points does the team usually complete on time?VelocityThe last 5 or 10 Iterations have finished.
Capacity and time How is the current Task allocated?Team CapacityAn Iteration is selected.
  1. 1
    Select Project and Team

    Reports uses context selector on the header bar; There is no separate Project/Team filter inside the page.

  2. 2
    Open Reports

    Select Type next to the Reports heading: Iteration Burndown, Velocity or Team Capacity.

  3. 3
    Select time

    Burndown and Team Capacity use Iteration picker. Velocity uses Window = Last 5 or Last 10 sprints.

  4. 4
    Read data status first

    If the newspaper page has no history or no data, resolve the cause before using the data.

Reports are only available to Workspace Admins and assigned Project Admins. Editors and accounts without Project rights cannot open Reports. The entire report is is read-only.

10.2

Read Iteration Burndown

Burndown combines US/DE Task and Points hours on two different axes.

Data stringUnitHow to understand
Task To DoHoursTotal Task ToDo at the end of each day. The value should gradually decrease as work progresses.
IdealHoursThe ideal reduction line from the total Task Estimate at the time Iteration starts to 0 on the last working day.
AcceptedPointsUS/DE's cumulative Plan Estimate has reached Accepted or Release as of each date.
  1. 1
    Select Iteration

    Use the previous button, Iteration list and the following button. Confirm the correct date range is displayed.

  2. 2
    Compare ToDo with Ideal

    Remaining To Do is higher than Ideal at the latest snapshot date which is understood as Behind plan; equal or lower is On track.

  3. 3
    Read Accepted Points separately

    Accepted uses Points axis. Do not take Points to deduct directly from ToDo Hours.

  4. 4
    Check continuity

    Burndown uses end-of-day snapshots. Dates missing history must be displayed as having no data, not automatically concatenated or rebuilt from today's value.

Burndown history is frozen. Changing today's To Do, Estimate, or scope does not rewrite the previous day's snapshot. The ideal also remains unchanged when the Task is added or re-estimated after the Iteration begins.

When Iteration does not have daily history, the report is displayed No burndown to show and do not draw Ideal if start baseline has not been written.

10.3

Read Velocity

Velocity separates work accepted on time, late, and unaccepted.

GroupConditionsDoes it count towards Velocity?
Accepted During IterationUS/DE reaches Accepted or Release no later than the Iteration end date.Yes. This is the source of Trend and average values.
Accepted After IterationUS/DE is accepted after Iteration has ended.No; Used for context only.
Not AcceptedUS/DE is not currently in Accepted or Release.No; Used for context only.
  1. 1
    Select Window

    Last 5 sprints focus on the near trend; Last 10 sprints give a more stable picture when enough data is available.

  2. 2
    Read each stacked column

    The three-part sum is all US/DE Points currently assigned to that Iteration.

  3. 3
    Read Trend and Averages

    Trend, Last 3, Best 3 and Worst 3 only count as Accepted During. Accepted After doesn't make Velocity better.

  4. 4
    Check available Iteration number

    When there are fewer than three Iterations, the report uses the entire available sample and must show the actual sample size.

Velocity is a classification based on current data. Moving US/DE into or out of an old Iteration, changing Plan Estimate or reopening items can cause the old chart to change. This report does not use frozen snapshots like Burndown.

Accepted or Release missing acceptedDate is a data quality error. Don't guess whether the item belongs to During or After.

10.4

Read Team Capacity

Report uses the same Capacity source and Task hours with Track → Team Status.

IndexSourceHow to understand
CapacityCapacity according to Member in Iteration.Available hours planned.
EstimateTotal Task Estimate.Initial estimate of Tasks in scope.
ToDoTotal current Task ToDo.Remaining volume updated by user.
ActualCurrent Actual Task Total.Actual time recorded; may be larger than Estimate.
  1. 1
    Select Iteration

    Changing Iteration will recalculate the four totals and the entire Team/Member line.

  2. 2
    Read by Team scope

    Select a Team to view that Team separately. All Teams displays Teams into groups and can open Members below.

  3. 3
    Compare four hour numbers

    Read values as independent data. ToDo is not equal to Estimate except Actual and Actual is not limited by Estimate.

  4. 4
    Check special Member

    Member with Capacity but no Task is still displayed. Tasks that do not have an Owner are under Unassigned with Capacity 0h.

Do not adjust Capacity in Reports. To change Capacity, go back to Track → Team Status. The report does not create a separate Capacity store.

10.5

Understand the scope and timing of data

The same update operation can affect three reports differently.

ReportData typeWhen source data changes
Iteration BurndownStart baseline and daily snapshot have frozen.Only the current date or future snapshot changes; History has been kept intact.
VelocityReclassify the current assignment, state, acceptedDate and Plan Estimate.The chart of the old Iteration may change.
Team CapacityProjection directly from Capacity and current Task time.Re-display immediately using the latest data in the current scope.

Selected Team only retrieves that Team's data. All Teams summarizes the Teams in the Project and must eliminate duplicates according to stable IDs. Do not manually add the number of All Teams to the number of each Team.

Workspace timezone usage date. When comparing Accepted During/After or end-of-day snapshots, check the Iteration date and timezone before concluding.

10.6

Distinguishes zero from missing data

Do not use an empty status as evidence that Team is not working.

Notice or indicationMeaningNeeds checking
No daily historyBurndown does not have a snapshot at the end of the day.Check the snapshot process, start date, and Iteration history.
No start baselineThe total Task Estimate was not recorded at the time Iteration started.Do not use or draw Ideal yourself.
No completed Iteration with workVelocity does not have a qualified Iteration in scope yet.End date and US/DE assigning.
No planned capacity and no scoped task hoursTeam Capacity does not have both Capacity and Task hours.Iteration, Team, Capacity record and Task assignment.
0h or 0 PointsThere is valid data and the measured value is 0.Compare the same scope, data source, and time period.

Do not interpolate missing history, do not replace null with 0, and do not construct graphs from fixture/mockup for operational reporting.

10.7

Troubleshooting

Check permissions, scope, timing, and data quality in order.

01
Can't see the Reports menu

Confirm the account is Workspace Admin or Admin of the selected Project. Editor does not have Reports permission.

02
Can't see Iteration to select

Check Project, Team and date range. Burndown/Capacity uses an Iteration; Velocity only takes Iteration that has ended and has US/DE.

03
Burndown is empty

Read daily history and start baseline notifications. Do not use the current Task value to manually reconstruct the history.

05
Velocity changed in old Iteration

Check that US/DE has just changed Iteration, Plan Estimate, state or acceptedDate. This is a recalculated report according to the current assignment.

06
Capacity is different from Team Status

Compare with Project, Team and Iteration; Check Member, Task Owner and data loading time.

07
Actual is larger than Estimate

This may be valid data. Actual is not capped and ToDo is not inferred from Estimate − Actual.

08
The number of All Teams is unusually large

Check for items or Tasks with duplicate IDs across multiple Teams. Do not add the number of each Team to the total of All Teams.

Export, saved report configurations, and custom date ranges are not currently covered by the guidance.

Check yourself before moving on to the next section
  • Did you know Burndown uses Hours and Points on two axes?
  • Do you know which part of Velocity is used for Trend?
  • Did you know that Team Capacity is a read-only report from Team Status?
  • Have you distinguished the number 0 from the state of no data?
