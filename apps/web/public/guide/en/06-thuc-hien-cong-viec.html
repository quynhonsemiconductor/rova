Rova User Guide/06. Work Execution
PART 06 · PERFORMING THE WORK

Monitor execution using Task

Each Task is a specific task under User Story or Defect. During the work process, you update the person in charge, status and hours directly on the Task.

After this chapter, you will be able to
  • Opens the Task list of a US or DE.
  • Create a child Task and assign it to the correct Owner.
  • Update Task State according to actual progress.
  • Distinguish between Estimate, To Do and Actual.
  • Added description, documentation, and view change history.
06.1

Open the US or Defect Task list

Task does not appear as an independent line in the Backlog. Open the parent Work Item and then switch to the Tasks tab.

  1. 1
    Open US or DE to be performed

    Find the Work Item from Backlog, Iteration Status, Team Status or the Search box on the top bar, then select the item ID.

  2. 2
    Select the Tasks tab

    The number before the tab name indicates the number of child Tasks present. The list only displays Tasks belonging to the currently open Work Item.

  3. 3
    Read the Task list

    The main columns include Rank, ID, Name, State, Owner, Project, Teams, To Do, Actuals and Estimate. The Totals line adds each hour field separately.

  4. 4
    Open the Task to be processed

    Select ID as TA-22 to open Task Detail. Here you can update content, status, Owner and time.

Task follows the parent Work Item

Task inherits Project, Team and Iteration from parent US/DE. Task does not have its own Iteration and does not appear as an independent item in the Backlog.

06.2

Create a child Task

Separate US/DE into tasks specific enough that one person can receive and update progress.

  1. 1
    Open the Tasks tab and select Add Task

    A new task will be created under the correct open US or DE. Check the parent Work Item before importing.

  2. 2
    Enter Name

    Write a specific action, for example Build a Priority filter. Name is a required field.

  3. 3
    Enter the initial time

    Fill in Estimate if there is an estimate. To Do and Actuals can be entered separately; Do not enter negative numbers.

  4. 4
    Select Owner

    Select a valid member of the parent Team or — No Entry — if the Task has not been assigned.

  5. 5
    Save Task

    Select Create Task for quick creation. Select Create with details when you want to immediately switch to the detail page to add content.

RESULTS Task appears in the Tasks tab of the parent US/DE

Check ID, Name, State, Owner and three hour values in the list. New task uses state Defined.

06.3

Assign Task to the right person

Owner indicates the main responsible person. The selection list depends on the Team of the parent Work Item.

01
Owner

The person responsible for the Task. You can choose when creating or updating in Task Detail and Tasks list.

02
Dev Owner

Additional field on Task Detail to recognize the developer when the Team process uses this role.

03
— No Entry —

Used when the Task owner has not been identified. The task is still created but needs to be reassigned before tracking the individual.

The Owner list only includes valid members of the parent Team. If you don't see a person, check the US/DE Team and that person's membership; Don't change the Team just to make the name appear.

06.4

Update Task status

Task uses its own set of states, shorter than the User Story and Defect states.

1

Defined

Task has been recorded but has not yet started execution.

→
2

In-Progress

Task is being executed. Switch to this state when work has actually begun.

→
3

Completed

Task completed. Check Actual and To Do before closing so that the hours reflect reality.

You can change Task State in the Tasks, Task Detail or Team Status tab if you have access to that screen. When all child Tasks of the same US/DE are Completed, the system automatically converts the parent Work Item to Completed. If you reopen any Task, the Work Item will automatically return to In-Progress.

Changing status does not automatically update the time

Completed or reopened Task does not change Estimate, To Do or Actual. The executor must update the hour values ​​separately.

06.5

Update Estimate, To Do and Actual

Three schools use the same hour unit but answer three different questions.

01
Estimate

Estimated total number of hours to complete the Task at the time of planning.

02
To Do

Hours remaining according to the operator's current assessment.

03
Actual

Number of hours performed and entered directly on Task.

When creating a Task, if you enter Estimate and leave To Do blank, the system copies Estimate to To Do exactly once. Once the Task has been created, the three fields operate independently: editing one field does not automatically recalculate the other two fields.

EXAMPLE

After a work session

Task was created with an Estimate of 6 hours and an initial To Do of 6 hours.

  • 1
    Worked 2 hours

    The operator enters Actual = 2.

  • 2
    About 4 hours left

    The user enters To Do = 4.

  • 3
    Estimate is still 6

    The system does not use the required formula Actual + To Do = Estimate.

Task Detail uses field Actual to enter the time directly; This tutorial does not use a separate Timesheet or Time Entry screen.

06.6

Add information and view history

Use Task Detail when you need to specify actions, attach documents, or check changes.

1
Description

Describe the scope, required results or technical notes of the Task.

2
Attachments

Attach files directly related to work; Avoid giving out passwords or sensitive data.

3
Linked Items

Link related items when cross-searching is needed. The parent Work Product is still displayed separately in the details panel.

4
Notes and Comments

Notes saves Task notes; Comments are used for communication over time.

5
Revision History

View Task updates, including changes to status, person in charge, or fields, that have now been recorded.

06.7

Troubleshooting

Check the parent Work Item, Team and permissions before recreating or editing data.

01
Tasks tab not visible

Check the open item is User Story or Defect. Task Detail does not have a child Tasks tab.

02
Task not seen in Backlog

This is normal behavior. Open the parent US/DE or use Team Status to find Tasks by Iteration and Owner.

03
Can't find the person to select in Owner

Check if that person is a valid member of the parent Team or not. If it cannot be delivered, select No Entry and notify the Team manager.

05
To Do does not decrease when entering Actual

Two independent fields. Please update To Do according to the remaining reviews instead of waiting for the system to automatically subtract.

06
Time does not change when Completed

Correct according to current rules. The state does not automatically set To Do to 0 or change Actual.

07
US/DE failed to change status automatically

When all child Tasks are Completed, the parent item is automatically Completed; Reopening a Task will return the parent item to In-Progress.

Check yourself before moving on to the next section
  • Is the task under the correct US or DE?
  • Is Owner part of the parent Work Item's Team?
  • Does Task State reflect actual progress?
  • Have Estimate, To Do and Actual been updated separately?
