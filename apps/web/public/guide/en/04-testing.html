Rova User Guide/04. Testing
PART 04 · TESTING

Create Test Case and record test results

Test Case describes what to test for a User Story or Defect. Test Result records the results of each run on a particular Build.

After this chapter, you will be able to
  • Open the US/DE Test Case list.
  • Create and complete a Test Case.
  • Record Test Result for each run.
  • Read Last Verdict, Last Run and history.
  • Manage Test Case Type by Project.
04.1

Understand the Testing flow

Testing starts from the Work Item needs to verify and keep test content separate from the results of each run.

User Story or Defect → Test Case → Test Result

Work ItemIndicates a need or error that needs verification. A US/DE can have many Test Cases.

Test CaseDescribes the goal, conditions, input data, and expected results. Test Cases are always linked to an existing Work Product.

Test ResultRecord Build, run date, Verdict, duration and Tester of an execution. A Test Case can have many Results.

Do not overwrite Test Case to save run results. When running again on another Build, add a new Result to preserve the previous Pass, Fail or Blocked history.

04.2

Open Work Item Test Cases

Test Cases are located in the User Story or Defect details page, right after the Tasks tab.

  1. 1
    Open User Story or Defect

    From Backlog, Iteration Status or Quality, select the ID of the Work Item to be tested.

  2. 2
    Select the Test Cases tab

    The number on the tab shows how many Test Cases are linked to the Work Item.

  3. 3
    Read the list

    Use Search, Filters and Show Fields when the list is long. Select Test Case ID to open the details.

ColumnMeaningHow to use
NameBrief test objectives.Read Name first to avoid creating Test Case with the same target.
Type / MethodTest type and execution method: Manual or Automated.Used to find and group appropriate Test Cases.
Priority / OwnerPriority and responsible person.Check before starting execution.
Last VerdictVerdict of latest Result.Indicates the most recent test status, does not replace Result history.
Last RunDate of latest Result.Used to identify whether a Test Case has been run recently or not.
04.3

Create Test Case

Create Test Case from US/DE itself so that Rova can properly link Work Product, Project and Team.

  1. 1
    Select Add New

    In tab Test Cases, select Add New to open the Create Test Case form.

  2. 2
    Enter Name

    Write a clear, concise test objective. The Create button is locked when Name is empty.

  3. 3
    Check classification information

    Select the appropriate Type, Method, Priority, Owner and Assigned To. Project is taken from the current Work Item.

  4. 4
    Create and open details

    Select Create. The new Test Case is associated with US/DE and starts in an unrun state.

FieldHow to enterNote
NameState the main behavior or condition to be verified.Required; Each Test Case should have one main goal.
TypeSelect a Type configured for the Project, such as Acceptance, Functional, or Regression.Type list is configured for each Project.
MethodSelect Manual or Automated.Reflects how the Test Case is executed.
PrioritySelect Low, Normal, High or Urgent.Priority represents the order in which to test.
OwnerSelect the person responsible for the Test Case.Different from Assigned To.
Assigned ToSelect the person being assigned to do it or leave it Unassigned.Can be changed later on Test Case Detail.
04.4

Complete Test Case content

Fill in the conditions, inputs, and expected results so others can run it again without asking further questions.

ContentsShould writeShould be avoided
DescriptionSummary of scope and behavior to test.Repeat Name without adding context.
ObjectiveState target or verified Acceptance Criteria.Merge multiple unrelated targets.
PreconditionsRecord permissions, data, Project, Team and status required before running.Using implicit conditions that the Tester does not know.
InputWrite operations and test data in the correct order.Write generically like “function test”.
Expected ResultState observable and comparable results.Use vague words like “functions properly”.
PostconditionsIndicates remaining data or status after running.Ignore data that needs to be cleaned or restored.
Notes / AttachmentsAdd necessary instructions, files or evidence.Put the Pass/Fail conclusion here instead of Result.

Rova does not have a separate Test Steps list. Please use the pair Input and Expected Result to describe the test step and the results to observe.

04.5

Record a Test Result

Each Result represents one Test Case run on a Build and does not replace previous Results.

  1. 1
    Open Test Case Detail

    Select tab Results; The number on the tab is the total saved Result.

  2. 2
    Select Add Result

    Rova automatically populates the current Test Case and Work Product as read-only.

  3. 3
    Enter run information

    Enter Build, Date, Verdict, Duration, Tester and Notes as needed.

  4. 4
    Save Result

    Select Save. New results are added to the history and old results are not deleted.

  5. 5
    Check roll-up

    Go back to Test Case and confirm Last Verdict, Last Run reflects the latest Result.

FieldHow to enterNote
BuildName or code of the instance under test.Required; Use uniform conventions for easy tracking.
DateActual date of test execution.Affects the Result that is considered the latest.
VerdictSelect Pass, Fail, Blocked, Error or Inconclusive.Only select Pass when it has run and has enough evidence.
DurationMinutes taken; Use numbers from 0 and above.Do not enter hour in minute field.
TesterThe person who made the run.Different Owner and Assigned To of Test Case.
NotesRecord data, environment, blocker or additional evidence.Do not use Notes instead of Build or Verdict.
04.6

Read results and history

Read Last Verdict for the most recent results, then open Results when you need to understand the entire run history.

Last Verdict gets the Verdict of the latest Result. Last Run gets the date of that Result. If two results have the same date, Rova uses the date of creation to determine the newer version.

AreaIndicatesWhen to use
Test Cases listLast Verdict and Last Run of each Test Case.Quickly check coverage and latest status.
Results listBuild, Date, Work Product, Verdict, Duration and Tester of each run.Compare results between multiple Builds or runs.
Result DetailInformation and attachments of a specific Result.Investigate Fail, Blocked, Error or Inconclusive.
Revision HistoryChanges recorded on Test Case or Result.Trace who changed the data and what changed.
04.7

Manage Test Case Type

Workspace Admin manages a separate Type list for each Project.

  1. 1
    Open Project

    Enter Settings → Workspaces & Projects, select the Project to configure and open the tab Details.

  2. 2
    Find Test Case Types

    The new project has default Types: Acceptance, Functional, Regression, Performance and Usability.

  3. 3
    Add Type

    Select Add New, enter a unique name in Project and then save.

  4. 4
    Stop using Type

    Select Remove and confirm. Type no longer appears when creating a new one; Old Test Cases still retain historical value.

04.8

Troubleshooting

Check the latest Work Product, required data and Result before recreating the record.

01
Test Cases tab not visible

Confirm you have the User Story or Defect Detail open and have permission to view the Work Item in that Project/Team.

02
Create is locked

Enter Name and check Type, Method, Priority, Owner, Assigned To before creating.

03
Test Case is not correct Work Product

Go back to US/DE and create it from the Test Cases tab of that same Work Item; Do not create another copy to cover the link error.

05
Save Result is locked

Check Build, Date and Tester. Duration cannot be less than 0.

06
Last Verdict was not as expected

Open the Results list and check Date. Last Verdict takes the latest Result, not the just opened Result.

07
Can't see the Type to select

Ask Workspace Admin to check the Test Case Types of the correct Project; Type may have been discontinued.

Check your understanding
  • Is the Test Case linked to the correct User Story or Defect?
  • Is Input and Expected Result enough for others to run again?
  • Is the Result correct for Build, Date, Verdict and Tester?
  • Are you reading the latest result or a historical result?
