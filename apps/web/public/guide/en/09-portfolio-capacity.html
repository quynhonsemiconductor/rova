PART 09 · PORTFOLIO & CAPACITY

From big goals to realistic capacity plans

Portfolio Items organizes goals according to the sequence Epic → Feature → User Story/Defect. Capacity Planning allocates the Feature of a Release to Teams in the plan without changing the Feature's original Project or Implementation Team.

After this chapter, you will be able to
  • Select the correct scope when viewing Epic or Feature.
  • Create and update Portfolio Item to correct level.
  • Read progress by Estimate and Count.
  • Create Capacity Plan according to a Release.
  • Allocate Feature, Publish and reopen Plan when needed.
09.1

Open Portfolio Items in the correct scope

Team scope determines the type of Portfolio Items you can view.

  1. 1
    Select the correct Project

    Open the context selector on the top bar and select the Project you want to manage.

  2. 2
    Select Team or All Teams

    Use All Teams when viewing Project-level Epic. Select a specific Team when focusing on that Team's Feature.

  3. 3
    Open Portfolio → Portfolio Items

    Select Type = Epic or Feature. Use Search portfolio, Filters and Show Fields to narrow down the list.

  4. 4
    Check the selected scope header

    Reconcile Project · Team on top before creating, editing or archiving.

Epic only appears in All Teams. While on a specific Team, Type = Epic may not display data. This is scoped behavior, not lost Epic.

Workspace Admin and Project Admin can manage Portfolio Items within the granted scope. Editors or accounts that do not have Project rights do not use this screen.

09.2

Distinguishing between Epic and Feature

Choose the right level to avoid bringing a large target to the Team or creating a Feature that is too broad.

ObjectUsed to describeScope and binding
EpicBig goal at Project level, used to group Features with the same result direction.Belongs to a Project; There is no direct Team and Release. Can contain multiple Features.
FeatureProduct capabilities can be deployed and progress tracked by the Team.Belongs to a Project; You can choose Team, Epic, Release and Owner. US/DE links directly to Feature.

Capacity Planning only allocates Features. Epic is used to guide and synthesize progress; Do not include Epic in the Capacity Plan.

Archive still holds history. Epics are only archived when there are no active child Features; This operation does not automatically archive child features.

09.3

Create and update Portfolio Item

Prepare the correct Project, Owner and parentage before saving.

When creatingMain fieldPoint to check
EpicName, Project, Owner, State, Preliminary Estimate.Do not select Team or Release.
FeatureName, Owner, Team, Release, Epic, State, Preliminary Estimate, Description.Epic, Team and Release must be the same Project.
  1. 1
    Select the Type to create

    On Portfolio Items, select Epic or Feature and then use the corresponding New button.

  2. 2
    Enter Name and Owner

    The name should describe the desired result. The Owner list depends on valid rights and membership.

  3. 3
    Complete the relationship

    For Feature, select Team, Release and Epic once defined. Select Epic = Unassigned if there is no parent Epic.

  4. 4
    Choose how to complete

    Create saves and returns to the list. Create with details opens the details page to add Description, Notes, Attachments and What Success Looks Like.

  5. 5
    Check Children

    Epic Children show Feature; Feature Children shows the User Story/Defect and Task below.

Feature does not have its own Plan Estimate. Preliminary Estimate and Refined Estimate are Feature-level estimates; Plan Estimate is located in User Story/Defect and is used for rollups.

09.4

Read Portfolio progress

The two percentage columns answer two different questions.

IndexHow to understandWhen appropriate
% Done by Est.Plan Estimate of US/DE in Accepted or Release divided by total Plan Estimate.When items have different sizes and Plan Estimate is fully entered.
% Done by CountNumber of US/DE in Accepted or Release divided by total number of US/DE.When you need to quickly read the number of completed items.

With Feature, data taken from US/DE links directly. With Epic, aggregated data from US/DE belongs to active sub-Features. Tasks are not counted directly.

Completed is not Accepted in Portfolio. US/DE only enters the numerator when in Accepted or Release.

When the denominator is 0, the interface displays 0%. Please open Children to check for items that are missing Plan Estimate or have no data before concluding.

09.5

Create Capacity Plan

Each Plan belongs to a Project, references a Release and uses a fixed unit.

  1. 1
    Open Portfolio → Capacity Planning

    Check Project on the top bar. Use Search plans, Filters or Show Fields when the list has many Plans.

  2. 2
    Select Add New

    The form displays Project, Plan Type = Single Release and Portfolio Item Type = Feature.

  3. 3
    Enter Name and select Release

    Release is required and must belong to the current Project. Each Project + Release pair has only one Capacity Plan.

  4. 4
    Select Unit

    Select points to use Plan Estimate or items to use quantity. Units cannot be changed after creation.

  5. 5
    Select Create

    The new Plan is in Draft state and has not yet added Teams or Features.

09.6

Allocate Feature and Capacity to Team

Allocation only exists in the Plan and does not change the Feature's original Project or Team.

  1. 1
    Add Team to Plan

    Use Add Team and select Team under Project. Capacity is entered manually for this Plan and defaults to 0.

  2. 2
    Add Feature

    Add from the Features tab to include Not assigned, or add from an open Team to pre-assign that Team.

  3. 3
    Assign or divide allocation

    Use Planned Team Assignment for a Team. Use Allocate when dividing a Feature among multiple Teams.

  4. 4
    Read Demand and Capacity

    Demand is the total allocation of the Team. Compare Complete, Rollup, Estimated and Capacity to identify over- or under-estimation.

  5. 5
    Adjust as needed

    Unassign keeps the Feature in Plan and returns it to Not assigned. Remove from Plan removes all allocations but does not archive Features.

Warning is advisory only. Rollup greater than Estimated, Demand greater than Capacity or missing estimate need to be considered; The system is not self-balanced.

Capacity Forecast is a support tool in Draft. The value is applied only when the user confirms it and is not continuously recalculated.

09.7

Publish and reopen Capacity Plan

Check the selected scope, total Capacity and warnings before locking Plan.

ActionResultPoint to remember
Publish Without Updating FieldsSwitch Plan to Published and change visibility.Do not copy Release or planning date to Feature.
PublishSwitch to Published and update the Feature fields allowed when the date condition is valid.Do not change Feature's Project/Team and do not update US/DE.
Revert to DraftUnlock Plan to continue editing.Do not automatically undo values ​​copied in the previous Publish.

Published is read-only. If you want to add Team, change Capacity, add Feature or edit allocation, Admin must Revert to Draft first.

If the Plan date does not match the Release, the system can still Publish the visibility but cannot silently overwrite the Release on the Feature. Please read the results notice before leaving the page.

09.8

Troubleshooting

Check scope, permissions, and status before regenerating data.

01
Epic not found

Switch to All Teams, select Type = Epic and uncheck Search/Filters.

02
Feature or Owner not found

Check Project, Team, permissions and membership. The options in the form must be in the same Project.

03
Unable to archive Epic

Epic still has active child Feature. Remove the relationship or process the child Feature first.

05
Progress is 0%

Open Children, check the US/DE status and Plan Estimate. Completed is not considered Accepted.

06
Unable to create Capacity Plan

Check for Release required, Admin and Plan rights may already exist for the same Project + Release.

07
Unable to edit allocation

Plan is published or the account only has viewing rights. Revert to Draft using an authorized account.

08
Feature disappears after removing Team

Check the Features and Not assigned tabs. Remove Team must keep Feature in Plan.

09
The total number is duplicated when dividing into multiple Teams

Plan total only counts each allocation once; Do not add the total line of the Feature.

Check yourself before moving on to the next section
  • Do you know why Epic only appears in All Teams?
  • You distinguish % Done by Est. with % Done by Count?
  • Do you know that the Unit of Capacity Plan cannot be changed after creation?
  • Have you distinguished between Unassign, Remove from Plan and Revert to Draft?
