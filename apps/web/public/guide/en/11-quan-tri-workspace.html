Rova User Guide / 11. Workspace Administration
PART 11 · WORKSPACE ADMINISTRATION

Manage the right people, the right Project and the right Team

Workspace Admin manage accounts in Workspace, Project structure, Teams and access rights. When handling, always differentiate Project permissions with Team member: a change in Team does not automatically grant or revoke Project permissions.

After this chapter, you will be able to
  • Select the correct Settings page for what you need to do.
  • Manage Users, Projects and Teams according to the correct scope.
  • Distinguish between Admin, Editor and Workspace Admin.
  • Read Permission Model and Audit Log.
  • Handle cases where User is not found or permissions are incorrect.
11.1

Open the admin area

Administrative functions are located in Settings and are divided according to the correct data type.

  1. 1
    Open Settings

    Select the Settings icon in the upper right corner. Group Personal is for personal accounts; group Workspace is for general administration.

  2. 2
    Select the correct page

    Use User Management for account; Workspaces & Projects for Project, Team and Project permissions; Permission Model to check permissions; Audit Log to view history.

  3. 3
    Check permissions before editing

    Workspace Admin can change structure. Admin and Editor only see parts that match the assigned Project; Admin buttons can be hidden or read-only.

PageUse when needed
User ManagementFind, invite and manage User status in Workspace.
Workspaces & ProjectsCreate or update Project, Project permissions, Team and Team members.
Permission ModelLook up the capabilities of each role. This is a read-only table.
Audit LogContrast who made which changes and when.
11.2

Managing Users in Workspace

User must exist and be active in Workspace before being granted Project permissions or added to a Team.

  1. 1
    Open User Management

    Read User, Email, Status and Last Login columns. Use Search users, Filters or Show Fields when the list is long.

  2. 2
    Invite members when needed

    Select Invite member and enter the correct organizational account. Inviting a User to Workspace does not automatically grant permissions to any Project.

  3. 3
    Status management

    Only keep Users in Active state when they still need to use the system. Status changes affect the entire Workspace, so you must check related Projects and Teams before implementing.

  4. 4
    Open Manage Access

    Use this button to view or change the User's Project permissions. The same person can be Admin in one Project, Editor in another Project and have no rights in the remaining Project.

Do not use Team to replace Project permissions. Users who do not have the appropriate Project permissions will not be valid candidates just because you want to add them to the Team.

11.3

Project Management

Workspaces & Projects is the only place to manage the Workspace → Project → Team tree.

  1. 1
    Select Project from the tree on the left

    The Projects screen displays the Key, Project name, Status and Team number. Select a Project to open Details, Users & Permissions and Teams.

  2. 2
    Create Project

    Select Create project. Enter name and Project key; The key uses capital letters and numbers, is 1–10 characters long, does not overlap and does not change after creation.

  3. 3
    Update Details

    Check Status, start/end date, Project owner and Description. Project owner is business information, does not grant Project rights itself.

  4. 4
    Estimation configuration

    Preliminary Estimate maps XS–XL to Points; Hours per point is used by Capacity Planning and Reports. Only save positive values ​​that match Project's estimation method.

Archive used when Project stops working but needs to keep history; can be restored from the Archive page. Delete is used when deletion is allowed and must go through a confirmation step. If the Project still has dependencies, the system may refuse to delete it.

11.4

Assign Project permissions

Grant permissions at the Users & Permissions tab of the Project or via Manage Access of the User.

RoleScopeHow to use
Workspace AdminComplete Workspace.Displayed with the label Workspace Admin; There is no Access Level change dropdown and no Remove access button.
AdminOne Project · All Teams.Managing delivery activities in Project; does not administer the Workspace structure.
EditorA Project · Team is assigned.Requires at least one active Team; Work within the assigned Team scope.
Not assignedNo Project scope.Project is hidden from the list and direct link is denied.
  1. 1
    Open Users & Permissions

    The list displays User, Status, Access Level and Action of the currently selected Project.

  2. 2
    Select Add existing user

    Select only active Users in Workspace. This function does not create new accounts.

  3. 3
    Select Access Level

    Admin always has All Teams. With Editor, select at least one active Team before saving.

  4. 4
    Check the scope again

    The new permission takes effect on the next request. If the old screen has not changed, reload and check the context selector.

Workspace Admin is a system permission. They appear in the Project list for administrators to recognize, but do not require a separate Admin or Editor license.

11.5

Team and member management

Each Team belongs to a Project; membership determines who participates in operations in that Team.

  1. 1
    Open the Teams tab

    The list displays Key, Team, Lead, Status, number of Members and Actions.

  2. 2
    Create or edit a Team

    Team name is required. The team key is 2–10 characters long, uses capital letters and numbers, cannot be duplicated in the Project and does not change after the first save.

  3. 3
    Add member

    Select Add member. Candidates must be Active and qualified in Project: Admin, Editor assigned appropriately or Workspace Admin active.

  4. 4
    Select Team Lead

    Team Lead must be an Active member of the Team. This role is responsible information within the Team, does not create additional system rights.

  5. 5
    Deactivate when Team stops working

    Do not assign new Work Items to inactive Teams. Check the relevant Work Item, Iteration and Owner before changing the status.

Workspace Admin is not automatically a member of every Team. They can be added to a Team to be Project Owner, Team Lead or Work Item Owner when qualified. Removing them from the Team only removes active membership, does not revoke Workspace Admin rights.

11.6

Read Permission Model

Permission Model is a fixed permission lookup table for Workspace Admin, Admin and Editor.

Each line is a group of functions such as Backlog, Timeboxes, Quality, Portfolio, Capacity Planning, Reports or Settings. Values Full, view, edit or mark -- indicates the operation level of the role.

Unable to create custom role or edit permission matrix. When a user is missing an action, check their role, Project, and Team; Don't look for separate configuration buttons for each small permission.

Part No Access explains the safe behavior: Ungranted projects are hidden from the list, picker, and navigation; Access using direct URL is denied.

11.7

View Audit Log

Audit Log is a reference source when you need to know whether a change has occurred or not.

  1. 1
    Open Audit Log

    Each line displays Time, Actor and Details.

  2. 2
    Filter data

    Use Filter this page, Filters and Show Fields to narrow the list according to the content being investigated.

  3. 3
    Read Details

    Detail describes the type of event, object and content that is easy to understand, for example creating a Project, renaming a Project, adding a Team member or granting Project permissions.

  4. 4
    Compare scope

    Compare Actor, time and correct Project/Team before concluding. Audit Log is read-only; Not used to undo changes.

11.8

Troubleshooting

Check the order of Workspace account → Project permissions → Team membership.

01
User not found when Add existing user

Check that the User is already in the Workspace, is Active and has not been granted Project rights.

02
Editor has no Team to choose from

Create or activate a Team first. Editor needs at least one Active Team in the Project.

03
Added to Team but still can't access Project

Team membership does not grant Project Access. Go back to Users & Permissions and level Admin or Editor accordingly.

05
Cannot change or delete the Workspace Admin line

This is a system permission line, used only for identification. Do not grant additional Admin/Editor to the same Project.

06
Workspace Admin does not appear in Owner

Add them as Active members of the currently selected Team. Workspace Admin rights allow creating US/DE but do not make the name appear in the Owner list.

07
Project owner does not have management rights

Project owner is metadata. Grant a separate Admin or Editor if that person needs to access the system.

08
Permissions have just been changed but the interface has not been updated

Reload the page, check for the next request and select Project/Team again in the context selector.

09
Cannot Archive or Delete Project

Read dependency messages and assertion steps. Use Archive when you need to preserve history and Delete only when the data is actually allowed to be deleted.

Check yourself before moving on to the next section
  • Have you distinguished between Project and Team member rights?
  • Do you know that Admin and Editor are different in Team scope?
  • Do you know why Workspace Admin doesn't have a button to change Access Level?
  • Do you know how to use Audit Log to compare changes?
