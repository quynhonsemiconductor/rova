Rova User Guide/04. Testing
PHẦN 04 · TESTING

Tạo Test Case và ghi nhận kết quả kiểm thử

Test Case mô tả điều cần kiểm tra cho một User Story hoặc Defect. Test Result ghi lại kết quả của từng lần chạy trên một Build cụ thể.

Sau phần này, bạn sẽ làm được
  • Mở danh sách Test Case của US/DE.
  • Tạo và hoàn thiện một Test Case.
  • Ghi Test Result cho từng lần chạy.
  • Đọc Last Verdict, Last Run và lịch sử.
  • Quản lý Test Case Type theo Project.
04.1

Hiểu luồng Testing

Testing bắt đầu từ Work Item cần xác minh và giữ riêng nội dung kiểm thử với kết quả của từng lần chạy.

User Story hoặc Defect → Test Case → Test Result

Work ItemNêu nhu cầu hoặc lỗi cần xác minh. Một US/DE có thể có nhiều Test Case.

Test CaseMô tả mục tiêu, điều kiện, dữ liệu đầu vào và kết quả mong đợi. Test Case luôn liên kết với một Work Product hiện tại.

Test ResultGhi Build, ngày chạy, Verdict, thời lượng và Tester của một lần thực thi. Một Test Case có thể có nhiều Result.

Không ghi đè Test Case để lưu kết quả chạy. Khi chạy lại trên Build khác, hãy thêm Result mới để giữ được lịch sử Pass, Fail hoặc Blocked trước đó.

04.2

Mở Test Cases của Work Item

Test Cases nằm trong trang chi tiết của User Story hoặc Defect, ngay sau tab Tasks.

  1. 1
    Mở User Story hoặc Defect

    Từ Backlog, Iteration Status hoặc Quality, chọn ID của Work Item cần kiểm thử.

  2. 2
    Chọn tab Test Cases

    Con số trên tab cho biết tổng Test Case đang liên kết với Work Item.

  3. 3
    Đọc danh sách

    Dùng Search, Filters và Show Fields khi danh sách dài. Chọn ID Test Case để mở chi tiết.

CộtÝ nghĩaCách dùng
NameMục tiêu kiểm thử ngắn gọn.Đọc Name trước để tránh tạo Test Case trùng mục tiêu.
Type / MethodLoại kiểm thử và cách chạy Manual hoặc Automated.Dùng để tìm và phân nhóm Test Case phù hợp.
Priority / OwnerMức ưu tiên và người chịu trách nhiệm.Kiểm tra trước khi bắt đầu thực thi.
Last VerdictVerdict của Result mới nhất.Cho biết trạng thái kiểm thử gần nhất, không thay thế lịch sử Result.
Last RunNgày của Result mới nhất.Dùng để nhận biết Test Case đã được chạy gần đây hay chưa.
04.3

Tạo Test Case

Tạo Test Case từ chính US/DE để Rova tự liên kết đúng Work Product, Project và Team.

  1. 1
    Chọn Add New

    Trong tab Test Cases, chọn Add New để mở form Create Test Case.

  2. 2
    Nhập Name

    Viết một mục tiêu kiểm thử rõ ràng, ngắn gọn. Nút Create bị khóa khi Name còn trống.

  3. 3
    Kiểm tra thông tin phân loại

    Chọn Type, Method, Priority, Owner và Assigned To phù hợp. Project được lấy từ Work Item hiện tại.

  4. 4
    Tạo và mở chi tiết

    Chọn Create. Test Case mới được liên kết với US/DE và bắt đầu ở trạng thái chưa có kết quả chạy.

TrườngCách nhậpLưu ý
NameNêu hành vi hoặc điều kiện chính cần xác minh.Bắt buộc; mỗi Test Case nên có một mục tiêu chính.
TypeChọn Type của Project, ví dụ Acceptance, Functional hoặc Regression.Danh sách Type được cấu hình theo từng Project.
MethodChọn Manual hoặc Automated.Phản ánh cách Test Case được thực thi.
PriorityChọn Low, Normal, High hoặc Urgent.Priority thể hiện thứ tự cần kiểm thử.
OwnerChọn người chịu trách nhiệm cho Test Case.Khác với Assigned To.
Assigned ToChọn người đang được giao thực hiện hoặc để Unassigned.Có thể thay đổi sau trên Test Case Detail.
04.4

Hoàn thiện nội dung Test Case

Điền đủ điều kiện, đầu vào và kết quả mong đợi để người khác có thể chạy lại mà không cần hỏi thêm.

Nội dungNên viếtCần tránh
DescriptionTóm tắt phạm vi và hành vi cần kiểm tra.Lặp lại Name mà không bổ sung ngữ cảnh.
ObjectiveNêu mục tiêu hoặc Acceptance Criteria được xác minh.Gộp nhiều mục tiêu không liên quan.
PreconditionsGhi quyền, dữ liệu, Project, Team và trạng thái cần có trước khi chạy.Dùng điều kiện ngầm mà Tester không biết.
InputGhi thao tác và dữ liệu kiểm thử theo đúng thứ tự.Viết chung chung như “thử chức năng”.
Expected ResultNêu kết quả quan sát được và có thể so sánh.Dùng từ mơ hồ như “hoạt động đúng”.
PostconditionsNêu dữ liệu hoặc trạng thái còn lại sau khi chạy.Bỏ qua dữ liệu cần dọn hoặc khôi phục.
Notes / AttachmentsBổ sung hướng dẫn, file hoặc bằng chứng cần thiết.Đưa kết luận Pass/Fail vào đây thay cho Result.

Rova không có danh sách Test Steps tách riêng. Hãy dùng cặp Input và Expected Result để mô tả bước kiểm thử và kết quả cần quan sát.

04.5

Ghi Test Result

Mỗi Result đại diện cho một lần chạy Test Case trên một Build và không thay thế các Result trước đó.

  1. 1
    Mở Test Case Detail

    Chọn tab Results; số trên tab là tổng Result đã lưu.

  2. 2
    Chọn Add Result

    Rova tự điền Test Case và Work Product hiện tại dưới dạng chỉ đọc.

  3. 3
    Nhập thông tin lần chạy

    Nhập Build, Date, Verdict, Duration, Tester và Notes nếu cần.

  4. 4
    Lưu Result

    Chọn Save. Result mới được thêm vào lịch sử và không xóa kết quả cũ.

  5. 5
    Kiểm tra roll-up

    Quay lại Test Case và xác nhận Last Verdict, Last Run phản ánh Result mới nhất.

TrườngCách nhậpLưu ý
BuildTên hoặc mã bản được kiểm thử.Bắt buộc; dùng quy ước thống nhất để dễ truy vết.
DateNgày thực tế thực hiện kiểm thử.Ảnh hưởng đến Result được xem là mới nhất.
VerdictChọn Pass, Fail, Blocked, Error hoặc Inconclusive.Chỉ chọn Pass khi đã chạy và có đủ bằng chứng.
DurationSố phút thực hiện; dùng số từ 0 trở lên.Không nhập giờ vào trường phút.
TesterNgười thực hiện lần chạy.Khác Owner và Assigned To của Test Case.
NotesGhi dữ liệu, môi trường, blocker hoặc bằng chứng bổ sung.Không dùng Notes thay cho Build hoặc Verdict.
04.6

Đọc kết quả và lịch sử

Đọc Last Verdict để biết kết quả gần nhất, sau đó mở Results khi cần hiểu toàn bộ lịch sử chạy.

Last Verdict lấy Verdict của Result mới nhất. Last Run lấy ngày của Result đó. Nếu hai Result có cùng ngày, Rova dùng thời điểm tạo để xác định bản mới hơn.

Khu vựcCho biếtKhi nào dùng
Test Cases listLast Verdict và Last Run của từng Test Case.Rà nhanh coverage và tình trạng gần nhất.
Results listBuild, Date, Work Product, Verdict, Duration và Tester của từng lần chạy.So sánh kết quả giữa nhiều Build hoặc lần chạy.
Result DetailThông tin và file đính kèm của một Result cụ thể.Điều tra Fail, Blocked, Error hoặc Inconclusive.
Revision HistoryCác thay đổi đã ghi nhận trên Test Case hoặc Result.Truy vết ai thay đổi dữ liệu và thay đổi gì.
04.7

Quản lý Test Case Type

Workspace Admin quản lý danh sách Type riêng cho từng Project.

  1. 1
    Mở Project

    Vào Settings → Workspaces & Projects, chọn Project cần cấu hình và mở tab Details.

  2. 2
    Tìm Test Case Types

    Project mới có các Type mặc định: Acceptance, Functional, Regression, Performance và Usability.

  3. 3
    Thêm Type

    Chọn Add New, nhập tên không trùng trong Project rồi lưu.

  4. 4
    Ngừng dùng Type

    Chọn Remove và xác nhận. Type không còn xuất hiện khi tạo mới; Test Case cũ vẫn giữ giá trị lịch sử.

04.8

Xử lý tình huống thường gặp

Kiểm tra Work Product, dữ liệu bắt buộc và Result mới nhất trước khi tạo lại bản ghi.

01
Không thấy tab Test Cases

Xác nhận bạn đang mở User Story hoặc Defect Detail và có quyền xem Work Item trong Project/Team đó.

02
Create đang bị khóa

Nhập Name và kiểm tra Type, Method, Priority, Owner, Assigned To trước khi tạo.

03
Test Case không đúng Work Product

Quay lại US/DE đúng rồi tạo từ tab Test Cases của chính Work Item đó; không tạo một bản khác để che lỗi liên kết.

05
Save Result đang bị khóa

Kiểm tra Build, Date và Tester. Duration không được nhỏ hơn 0.

06
Last Verdict không như dự kiến

Mở danh sách Results và kiểm tra Date. Last Verdict lấy từ Result mới nhất, không phải Result vừa mở.

07
Không thấy Type cần chọn

Nhờ Workspace Admin kiểm tra Test Case Types của đúng Project; Type có thể đã bị ngừng dùng.

Tự kiểm tra trước khi kết thúc
  • Test Case đã liên kết đúng User Story hoặc Defect chưa?
  • Input và Expected Result đã đủ để người khác chạy lại chưa?
  • Result có đúng Build, Date, Verdict và Tester chưa?
  • Bạn đang đọc kết quả mới nhất hay một Result lịch sử?
