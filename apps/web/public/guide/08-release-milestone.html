PHẦN 08 · RELEASE & MILESTONE

Quản lý mốc giao hàng và đọc tiến độ đúng nơi

Release xác định một cửa sổ giao hàng của Project. Milestone ghi nhận mốc quan trọng và có thể liên kết nhiều Release. Tạo và chỉnh hai đối tượng này tại Plan → Timeboxes; xem tiến độ Release tại Portfolio → Release Tracking.

Sau phần này, bạn sẽ làm được
  • Chọn đúng màn hình quản lý hoặc theo dõi Release.
  • Tạo Release với ngày và trạng thái hợp lệ.
  • Tạo Milestone và hiểu khi nào ngày được nhập tay.
  • Liên kết Work Item, Feature hoặc Epic đúng loại Artifacts.
  • Đọc các nhóm dữ liệu và biểu đồ Burnup trong Release Tracking.
08.1

Chọn đúng màn hình trước khi thao tác

Thông tin Release và số liệu tiến độ nằm ở hai khu vực khác nhau.

Khi cầnMở tạiThực hiện ở đây
Tạo hoặc sửa ReleasePlan → Timeboxes → ReleasesQuản lý Name, Theme, ngày, trạng thái, metadata, Release Notes và Artifacts.
Tạo hoặc sửa MilestonePlan → Timeboxes → MilestonesQuản lý mốc, ngày mục tiêu, Owner, phạm vi Project/Team, Release liên kết và Artifacts.
Đọc tiến độ ReleasePortfolio → Release TrackingĐọc các nhóm Feature/Work Item, trạng thái theo Points hoặc Count và biểu đồ Burnup.

Quyền truy cập: Workspace Admin và Admin của Project có thể quản lý Release/Milestone trong phạm vi được phép. Editor không dùng các màn hình lập kế hoạch này. Trước khi thao tác, hãy kiểm tra Project và Team trên thanh đầu trang.

Không tạo Release trong Release Tracking. Đây là màn hình theo dõi. Release Planning và phân tích Dependencies chưa phải chức năng đang hoạt động trong hướng dẫn này.

08.2

Tạo Release

Dùng Release khi cần xác định khoảng thời gian và mục tiêu cho một đợt giao hàng của Project.

Trước khi bắt đầu: chọn đúng Project, chuẩn bị tên Release, ngày bắt đầu, ngày giao dự kiến và trạng thái ban đầu.

TrườngCần nhập gìLưu ý
Release nameTên ngắn gọn cho đợt giao hàng.Bắt buộc và nên phân biệt được với các Release khác.
ThemeMục tiêu hoặc chủ đề chính.Có thể bổ sung chi tiết sau.
Start Date / Release DateKhoảng thời gian dự kiến.Release Date không được sớm hơn Start Date.
StatusPlanning, Active hoặc Accepted.Đây là trạng thái Release, độc lập với trạng thái US/DE.
DescriptionPhạm vi hoặc ghi chú ngắn.Không dùng thay cho Release Notes chi tiết.
  1. 1
    Mở Plan → Timeboxes

    Trong bộ chọn Timebox, chọn Releases. Danh sách chỉ hiển thị Release của Project hiện tại.

  2. 2
    Chọn Add New

    Form Create Release mở với các trường Release name, Theme, Start Date, Release Date, Status và Description.

  3. 3
    Nhập tên, ngày và trạng thái

    Chọn Planning khi Release còn đang chuẩn bị; Active khi đợt giao hàng đang diễn ra; Accepted khi kết quả đã được chấp nhận.

  4. 4
    Chọn cách hoàn tất

    Create Release lưu và quay lại danh sách. Create with details mở trang Release Detail để bổ sung metadata và nội dung chi tiết.

  5. 5
    Kiểm tra Release vừa tạo

    Đối chiếu tên, Project, ngày và State trên danh sách hoặc Release Detail trước khi gán Work Item.

Trong Release Detail, bạn có thể bổ sung Release Theme, Notes & Scope Deliverables, Release Notes, Planned Velocity, Plan Estimate và Version. Trang này không hiển thị Burnup hoặc tiến độ Accepted; các số đó nằm trong Release Tracking.

08.3

Tạo Milestone

Dùng Milestone cho một mốc demo, nghiệm thu hoặc kết quả quan trọng có thể trải qua nhiều Release.

  1. 1
    Mở Plan → Timeboxes → Milestones

    Màn hình hiển thị Name, Target Start Date, Target End Date và Status.

  2. 2
    Chọn Add New

    Nhập Milestone name; chọn Status, Owner và bổ sung Description hoặc Notes khi cần.

  3. 3
    Chọn ngày hoặc Release liên kết

    Nếu chưa chọn Associated Releases, nhập Target Start và Target End. Nếu chọn một hoặc nhiều Release, ngày mục tiêu sẽ được tính từ các Release đó.

  4. 4
    Chọn Create Milestone

    Sau khi lưu, mở Milestone Detail để kiểm tra ngày, trạng thái, Release liên kết và phạm vi Project/Team.

Trạng thái Milestone gồm Planned, At Risk, Met, Missed, Cancelled và Completed. Đây là trạng thái của mốc; không dùng thay cho trạng thái Release hoặc trạng thái Work Item.

Milestone không có velocity, Task Estimate hoặc quy tắc carry-over của Iteration.

08.4

Hiểu liên kết và ngày mục tiêu

Release và Milestone có thể được tạo theo bất kỳ thứ tự nào và liên kết nhiều-nhiều.

Tình trạng liên kếtCách xác định ngày MilestoneKhi thay đổi
Không có Release liên kếtTarget Start và Target End được nhập tay.Người có quyền có thể chỉnh trực tiếp hai ngày.
Có một ReleaseLấy Start Date và Release Date của Release đó.Ngày Milestone trở thành giá trị suy ra.
Có nhiều ReleaseTarget Start là ngày bắt đầu sớm nhất; Target End là ngày giao muộn nhất.Đổi danh sách Release sẽ tính lại khoảng ngày.
Gỡ toàn bộ ReleaseMilestone trở lại chế độ nhập ngày thủ công.Kiểm tra và nhập lại ngày phù hợp trước khi lưu.

Release và Milestone là hai quan hệ độc lập trên Work Item. Thay đổi Release của một US/DE không tự xóa các Milestone đã chọn. Khi Work Item đã có Release, danh sách Milestone mới để thêm chỉ hiển thị các Milestone liên kết với Release đó.

08.5

Quản lý Artifacts đúng loại

Artifacts là các đối tượng công việc hoặc Portfolio Item được liên kết với Release hoặc Milestone.

Phạm viArtifacts hợp lệQuy tắc cần nhớ
ReleaseUser Story, Defect và Feature được gán trực tiếp.Mỗi US/DE chỉ có tối đa một Release. Task và Epic không phải Release Artifact.
MilestoneStory, Defect, Feature và Epic; có thể bao gồm hậu duệ được kế thừa từ Feature/Epic.Một Work Item có thể thuộc nhiều Milestone nếu vẫn nằm trong phạm vi hợp lệ.
  1. 1
    Gán Release từ Work Item hoặc Feature

    Mở Backlog, Work Item Detail hoặc Portfolio Item phù hợp và chọn Release. Chọn Release khác sẽ thay thế liên kết Release cũ nhưng không đổi Iteration hoặc Milestone.

  2. 2
    Kiểm tra tab Release Artifacts

    Mở Release Detail → Artifacts để tìm và kiểm tra các item đã liên kết. Add Artifact cho phép chọn Story/Defect có sẵn; thao tác này không tạo Work Item mới.

  3. 3
    Gán Milestone bằng danh sách chọn nhiều

    Trên Work Item, chọn một hoặc nhiều Milestone hợp lệ. Các Milestone đã chọn phải luôn còn hiển thị khi bạn mở lại trường này.

  4. 4
    Kiểm tra Milestone Artifacts

    Đối chiếu item gán trực tiếp và các item được kế thừa qua Feature/Epic. Dữ liệu trùng phải chỉ được tính một lần.

Không dùng Add Artifact để thay thế luồng tạo công việc. Khi cần tạo US/DE hoặc Feature mới, hãy tạo ở Backlog hoặc Portfolio rồi gán Release/Milestone theo đúng trường của đối tượng.

08.6

Đọc Release Tracking

Dùng Portfolio → Release Tracking để xem phạm vi và tiến độ của Release đang chọn.

  1. 1
    Kiểm tra Project và Team

    Release Tracking dùng phạm vi toàn cục trên thanh đầu trang. Chuyển Team sẽ tính lại danh sách và biểu đồ; trang không có bộ lọc Project/Team thứ hai.

  2. 2
    Chọn Release

    Dùng nút trước, danh sách Release và nút sau ở đầu trang. Khoảng ngày bên cạnh tên là cửa sổ của Release đang đọc.

  3. 3
    Chọn Chart Unit

    Points cộng Plan Estimate của Story/Defect; Count đếm Story/Defect. Lựa chọn này áp dụng cho cả cột Status và Burnup.

  4. 4
    Chọn nhóm cần xem

    Features in Release là Feature gán trực tiếp; Derived Features là Feature xuất hiện do có Story/Defect con trong Release; Unparented Stories & Defects là item không có Feature cha.

  5. 5
    Đọc Status và Burnup

    Planned lấy Story/Defect thuộc Release. Accepted chỉ tính item ở trạng thái Accepted hoặc Release; Completed chưa được coi là Accepted.

Biểu đồ Burnup hiển thị Accepted, Planned, Preliminary Estimate và đường mục tiêu trong cửa sổ Release. Dòng Iteration bên dưới giúp đối chiếu các chu kỳ đi qua khoảng thời gian đó.

Khoảng trống lịch sử không phải số 0. Ngày chưa có snapshot được hiển thị thành khoảng trống. Không kết luận tiến độ bằng 0 nếu lịch sử đang thiếu hoặc chưa đầy đủ.

Dependencies · Future chỉ là nhãn cho chức năng tương lai; không dùng nó để đánh giá rủi ro phụ thuộc trong bản hiện tại.

08.7

Xử lý tình huống thường gặp

Kiểm tra quyền, phạm vi và quan hệ trước khi tạo lại dữ liệu.

01
Không thấy Release hoặc Milestone

Kiểm tra đúng Project, bỏ Search/Filters và xác nhận tài khoản có quyền Workspace Admin hoặc Admin tại Project đó.

02
Không tạo hoặc sửa được

Editor không có quyền quản lý Timeboxes. Liên hệ Project Admin thay vì yêu cầu thêm Team membership.

03
Ngày Milestone không chỉnh được

Milestone đang liên kết ít nhất một Release nên ngày được suy ra. Kiểm tra Associated Releases trước khi thay đổi liên kết.

05
Item không có trong Release Artifacts

Đối chiếu Project, loại item và trường Release. US/DE có thể đang thuộc Release khác; Task và Epic không xuất hiện trong danh sách này.

06
Không thấy Milestone để chọn trên Work Item

Nếu item đã có Release, chỉ Milestone liên kết với Release đó được đưa vào danh sách lựa chọn mới. Các Milestone đã chọn trước đó không tự mất.

07
Burnup trống hoặc đứt đoạn

Kiểm tra Release, phạm vi Team, Chart Unit và chất lượng lịch sử. Khoảng trống snapshot không được diễn giải thành số 0.

Tự kiểm tra trước khi sang phần tiếp theo
  • Bạn biết nơi tạo Release khác nơi đọc Release Tracking chưa?
  • Bạn biết khi nào ngày Milestone được nhập tay hoặc suy ra chưa?
  • Bạn phân biệt Release Artifact với Milestone Artifact chưa?
  • Bạn biết Completed chưa được tính vào Accepted trong Release Tracking chưa?
